# BOEKUNA iOS companion packaging

This directory is the native iOS packaging baseline for the existing BOEKUNA web product.
It intentionally does not duplicate accounting, OCR, billing, authentication or financial logic.

## Identity

- Product: `Boekuna`
- Bundle ID: `nl.boekuna.app`
- Marketing version: `1.0.0`
- Build number: `1`
- Initial device family: iPhone
- Minimum iOS: 17.0
- Start URL: `https://app.boekuna.nl/?login=1&app=1`

The Bundle ID and App Store Connect app record are managed in the Apple Developer account. The repository does not contain a Team ID, certificates, private keys, App Store Connect API keys or reviewer credentials.

## Native shell responsibilities

The SwiftUI/WKWebView shell adds only platform packaging behavior:

- persistent WKWebView website data for the existing BOEKUNA session;
- full-screen viewport so the web product can own its safe-area/visual-viewport behavior;
- native loading and network-failure states;
- JavaScript alert/confirm/prompt support;
- native handling for `mailto:` / `tel:` and new-window external links;
- download-to-share handoff for files generated by the web product;
- camera/photo permission descriptions for user-initiated document capture;
- a shared Xcode scheme and deterministic version/build identity.

Do not add a second financial engine, local account store, Stripe implementation, OCR implementation or Supabase secret to this target.

## Local simulator build

Requires macOS with Xcode 26+ and iOS SDK 26+. Full unsigned verification:

```bash
./ios/scripts/preflight.sh
```

Single simulator build:

```bash
xcodebuild \
  -project ios/Boekuna.xcodeproj \
  -scheme Boekuna \
  -configuration Debug \
  -sdk iphonesimulator \
  -destination 'generic/platform=iOS Simulator' \
  CODE_SIGNING_ALLOWED=NO \
  build
```

## Signing

The project uses automatic signing but deliberately leaves `DEVELOPMENT_TEAM` unset in source control.
Select the correct Apple team in Xcode or pass it at build time:

```bash
export DEVELOPMENT_TEAM='<APPLE_TEAM_ID>'
export BUILD_NUMBER='<UNUSED_POSITIVE_BUILD_NUMBER>'
./ios/scripts/archive.sh
```

The archive command uses the registered Bundle ID `nl.boekuna.app`. No signing certificate, provisioning profile or private key belongs in Git.

## TestFlight

Apple's supported route is archive -> App Store Connect -> TestFlight.
After a signed device build and TR2 physical-device acceptance:

```bash
export DEVELOPMENT_TEAM='<APPLE_TEAM_ID>'
export BUILD_NUMBER='<UNUSED_POSITIVE_BUILD_NUMBER>'
export UPLOAD_TO_TESTFLIGHT=1
./ios/scripts/archive.sh
```

This uploads the archive using Xcode's configured Apple account and automatic signing. Alternatively open the archive in Xcode Organizer and choose **Distribute App -> TestFlight & App Store**.

Before any upload:

1. set `BUILD_NUMBER` to an unused positive number for every new upload; the script overrides `CURRENT_PROJECT_VERSION` without committing signing settings;
2. confirm the selected Team owns `nl.boekuna.app`;
3. run the iOS CI build on the exact commit;
4. run TR2 on a physical iPhone against the exact archive/TestFlight build;
5. keep secrets and reviewer credentials out of the repository.

## Scope note

The shell identifies itself as `BoekunaNative/<version> Boekuna-iOS/<version>` so the existing web companion purchase guards are active. Purchase routes are also blocked for main-frame/new-window navigation. Persistent WKWebView data, camera/file input and the existing bookkeeping/OCR/authentication remain the product implementation. Download navigation enters WKDownload and shares each completed file; temporary files are removed after sharing.

The app loads the live web product. Companion-specific web fixes must be deployed and verified before testing the native archive. Physical-device acceptance, signing and Apple account suitability remain separate gates.
